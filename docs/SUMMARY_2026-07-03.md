## Bugs found and fixed

1. **`BWA_MEM` piped into `samtools view`, but the `bwa` biocontainer image
   doesn't include samtools** (separate BioContainers images per tool) →
   failed with exit 127, `samtools: command not found`.
   - Fix: `BWA_MEM` now emits a `.sam` file directly; SAM→BAM conversion
     moved into `SORT_DEDUP`, which already runs in a samtools container.
     See [`modules/bwa_mem.nf`](../modules/bwa_mem.nf).

2. **`samtools markdup` requires an `ms` mate-score tag**, which only exists
   after `samtools fixmate -m`, which in turn requires a name-sorted BAM →
   failed with `error, no ms score tag. Please run samtools fixmate first.`
   - Fix: `SORT_DEDUP` now runs the correct sequence: name-sort → fixmate →
     coordinate-sort → markdup → index. See
     [`modules/sort_dedup.nf`](../modules/sort_dedup.nf).

3. **`main.nf` param defaults unconditionally overwrote CLI `--reads` /
   `--reference` / `--outdir` overrides** (a common Nextflow gotcha — plain
   assignment in the script body runs after CLI parsing and clobbers it).
   - Fix: changed to `params.reads = params.reads ?: "s3://..."` pattern so
     CLI-provided values are respected. See [`main.nf`](../main.nf).

## Known non-blocking issue

Running Nextflow from a path containing spaces (`.../Job Search/...`)
produces a harmless warning during each process (`export: 'Search/...bin':
not a valid identifier`) because Nextflow appends the project `bin/`
directory to `PATH` unquoted. It didn't fail any process in this run since
`bin/` is currently empty. Worked around locally by running via a symlink
(`/tmp/nf-project`) without spaces. Revisit if custom scripts are ever added
to `bin/`.
